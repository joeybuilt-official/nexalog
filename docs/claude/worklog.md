# Worklog

Running record of what actually happened — **one line per meaningful change, written in the SAME
commit as the change.** Continuous / chronological view (`in-progress.md` is current *state*; this is
*history*). Newest first.

Nexalog has **no `CHANGELOG.md` and no `HISTORY.md`**, so this file *is* the repo's worklog target —
`scripts/check-docs.sh` auto-detects it. Do not start a `CHANGELOG.md` alongside it: one running log,
never two.

A change earns a line when it lands source, config, schema, or shipped docs. Trivial typo / format-only
commits need none. The line is part of the diff, not a follow-up — **shipped-but-unlogged counts as not
done** (`.claude/rules/documentation.md`).

## Format

`- YYYY-MM-DD · <what changed, imperative> · \`<where: file or area>\` · <initiative / queue-row, if any>`

Append-only, never pruned. On ship: promote the durable entry to `completed-features.md` and move the
`roadmap.md` initiative, in the same commit.

New `apps/web/lib/db/surface-unavailable.ts` matches Postgres `42P01` at any depth of the error's `cause` chain (drizzle wraps the driver error, and the nesting is a driver detail — the `code` is the contract) and converts it into **503 `{error:"surface_unavailable", code:"missing_relation", surface}`**, logged as `api.surface_unavailable` with the relation name so the operator can see why; every other error still propagates with its stack trace, and the relation name / SQL never reach the caller. **Why 503 and not an empty 200:** an empty delta tells the offline client "nothing changed since your cursor", it persists that cursor, and those rows are never pulled again — silently, permanently, indistinguishable from data loss, and the notes DO exist in the other store; a route whose tables are missing must never report success. **The subtler half is `/api/sync/mutations`:** it already caught per-op and returned `200 {status:"rejected"}`, and the shipped Flutter client treats `rejected` as TERMINAL (`SyncEngine` → `MutationQueue.markConflict`), **parking the user's queued write forever** — a wrong 200 that is worse than the 500 because it is silent. A missing relation now escapes that per-op catch and becomes the 503 the client retries. **Mobile is deliberately unchanged, and verified so:** `SyncEngine.sync()` catches `DioException` → `SyncStatus.offline`, keeps the last-synced mirror, and — the load-bearing part — 503 is a failed response, so `_pullDelta()` never reaches `setCursor` and the delta re-pulls intact once the surface is fixed; no UI change was needed because the empty-state bug the task warned about was in the *delta* shape, and a 503 cannot produce it.
