## 2. Premise corrections (operator brief vs reality)

Two of the brief's framing assumptions were wrong; the plan downstream changes
accordingly.

### 2a. Mobile is NOT a 3-of-18 WebView shell

Reality: the Flutter app is fully native (Riverpod + `super_editor` + custom
graph painter). 18+ screens already exist:

```
today · journal_list · journal_entry · inbox · queue · notes_list · note_editor
bookmarks · kind_surface (watch/reading/reference/sites) · reader · import
web_history · graph · chat (sessions + thread) · projects (list+detail)
dashboard · settings · admin · sign_in (only WebView) · billing · capture
quick_capture_sheet · search · plexo_history
```

Only WebView reference is OAuth sign-in. Bottom-tabs cover Today/Notes/Capture/
Bookmarks/Search; drawer adds Synthesis + Workspace groups.

**Real mobile gaps** (vs web):

- Voice-memo capture screen — **missing**. `speech_to_text` powers reader TUI
  only, not record-then-transcribe capture (`mobile/lib/src/features/.../voice_reader.dart`).
- Calendar — **missing**.
- Settings parity — partial (no denylist/retention surface confirmed yet).
- Detail polish across many surfaces (per-screen review deferred to phase work).

### 2b. `/srv/nexalog-v1/extension/` *does* exist (untracked)

Initial pass missed it because it's untracked. Reality: a working Manifest V3
Chrome clipper "Nexalog Bookmarks" v1.2.1 lives at
`/srv/nexalog-v1/extension/`. Features:

- Save-on-popup-open (no Save button), `POST /api/capture` `{kind:"url",content:url}`.
- Context menus (page / link / video+audio / highlight) — highlight → `kind:"text"`.
- Keyboard shortcut `Alt+Shift+S`. Omnibox `nx <query>` → `/api/search`.
- Web-history buffered batch every 30s → `POST /api/history` (≤200 visits).
- "Already saved" toolbar badge via `GET /api/history/exists?url=`.
- One-time `chrome.history` back-catalog import.
- Self-host instance config — `chrome.permissions.request` for new origin,
  persisted via `chrome.storage.sync.baseUrl`.
- Auth: **session cookie only** (`credentials:"include"`), no bearer/API key.

**Gaps**: missing `popup.css`, `options.js`, and `icons/icon{16,48,128}.png`
(referenced from manifest). No tests, no retry/backoff on history flush
failure, no version-update flow, no bearer-token path (which the mobile share
intent uses — see §3 T1b).

**Implication**: P5 (web clipper) is **finish + ship**, not new build —
smaller phase than the master plan first assumed.

### 2d. Canonical root causes (from optimization-plan.md, 2026-06-11)

- **RC1 — bookmarks render as notes (CONFIRMED).** `app/api/capture/route.ts:272-287`
  inserts a `notes` row for every capture incl. `kind='url'`; **3417/3455
  notes (99%) are URL bookmarks**. Search/notes lists conflate the two. Per
  the prior plan: P6a (notes filter) marked done — needs deploy-gap re-verify.
- **RC2 — Today page "old and irrelevant" (CONFIRMED, by design).**
  `lib/staleness.ts:153-157` scores off `createdAt` only; `last_visited_at` /
  `opened_at` are 100% NULL → ranking collapses to pure-oldest. Per the prior
  plan: P7b (Today rebuild) marked done — superseded RC2 via the queue ranker
  pipeline; needs deploy-gap re-verify.
- **RC3 — auto-categories messy (two layers).** Clean 25-tag controlled
  vocabulary is **dead in nav** (`bookmark-sidebar.tsx` unimported); emergent
  `theme_label` forest has 22 overlapping labels; graph entities all
  bare-typed `Entity` with dup nodes. Per the prior plan: P9a (vocab nav)
  marked done; P9c (entity typing) deferred (cross-repo Plexo work).
- **RC4 — retrieval architecturally sound; data layer empty.** Search
  pipeline good but `embedding_state = 4010 pending / 94 failed / 0 ready`
  → semantic search returns nothing. Notes had no FTS at the time (C2
  shipped this since: `drizzle/0013_notes_fts.sql`). **Draining the
  embedding backfill unlocks semantic search AND clustered themes —
  upstream of RC3 and RC4.** Per the prior plan: P8a Path B (local
  pgvector live) done; the backfill **drain itself is still open**.

## 3. Gaps confirmed (and extended)

### T1 — daily-driver trust

#### T1a · Mobile parity (revised scope)
Per §2a: not a porting job. Build voice-memo capture + calendar screens and
sweep detail parity per surface. Scope is days, not weeks.

#### T1b · Offline / local-first
- **Web has zero service worker.** No `sw.js`, no Workbox, no
  `serviceWorker.register`. PWA installs but goes blank offline.
- **Manifest's `share_target POST /app/share`** hits the network unconditionally
  — install the PWA, drop signal, share drops on the floor.
- Mobile share-receiver Activity (`ShareReceiverActivity.kt:51`) is **single
  attempt, no retry, no queue**. Flaky cell = lost capture.
- **Mobile in-app capture path IS local-first** via sqflite + outbox. Share
  intent path bypasses it.

#### T1c · Active resurfacing
- Queue ranker exists and is sound (§1). Surface gaps:
  - No daily digest / morning brief email or in-app card surfacing N picks.
  - No "forgotten" / "related-now" lens reusing pgvector + memoryThemes.
  - `feedbackSignals` rows for `snooze` and `weekend` actions are logged but
    produce no behaviour (`app/api/queue/feedback/route.ts:80` — explicit
    no-op).
  - **Plexo `/api/v1/memory/cluster/compute` 404s** (ADR-0003); auto-synthesis
    cron writes nothing in the default sweep
    (`app/api/cron/enrichment/route.ts:260-281` gated by
    `SCL_EMBEDDINGS_CLUSTERING==="true"`).
  - Local fallback `scripts/cluster-themes.ts` (k-means, k=18) exists but is
    **manual `tsx` only — no cron wire**.
  - `lib/themes/forest.ts:639-645` reads `memoryThemes`; search route comment
    at `app/api/search/route.ts:769` notes "memory_themes is unpopulated
    locally" — degraded silently to denormalised `capture_sources.themeLabel`.

### T2 — scales past a few hundred items

- **Saved smart-views + query language** — no query DSL exists. Search is
  one-string + tag/kind facets. Worth a dedicated ADR.
- **Web clipper** — does not exist (§2b). New build, not finish-up.
- **Inline cited-AI trust UX** — chat cites notes; needs hover-preview, jump-to,
  and confidence/source breakdown. Currently just an inline link.

### T3 — depth

- **Block transclusion** — Tiptap supports block IDs but no transclusion
  resolver in the editor / no fetch-by-block-id endpoint.
- **User-typed objects** — ADR-0004 already records the direction; no
  implementation. Ideas taxonomy (ADR-0008) ships *one* typed family.
- **Graph load-bearing decision** — ADR needed. Today the graph is **purely
  visual** (Plexo themes-forest projector + d3 viz); chat/search do not call
  `/api/graph`. `ideas.graphEpisodeId` column has **zero readers and writers
  anywhere in the codebase** — pure dead schema. Recommendation: de-emphasise
  the graph view to a sidebar gadget OR commit to graphiti ingestion and wire
  it; current half-state is just dead weight.
- **Spaced review** — no SR queue, no SM-2 / FSRS, no Anki-style scheduler.

## 4. Cross-cutting gaps surfaced by the audit

### 4a. Retrieval rough edges

- **Chat grounding does not use the fused RRF**
  (`app/api/chat/[sessionId]/messages/route.ts:300-332` — local FTS + pgvector
  + recent fill only). M2 (Tier-3 prior session) added an `rrf.ts` lib; chat
  was rewired in that PR. **Verify both sides converge to the same RRF k +
  candidate sizing.**
- **Lexical pre-fuse by raw `ts_rank_cd` magnitude**
  (`app/api/search/route.ts:606-612`) mixes capture+note ranks across different
  tsquery flavours (`plainto_tsquery` vs `websearch_to_tsquery`); the ranks are
  not commensurable. Should fuse via RRF, not magnitude.
- **RRF is unweighted.** Semantic and lexical contribute 1:1. There is a
  learned-weights system for the queue ranker but no analogue for search.

### 4b. Observability — §12 FAIL

- Zero `Effect.log` / `withSpan` / `@effect/opentelemetry` in `lib/` or `app/`.
- Zero `pino` / `winston`.
- 165 `console.*` sites across 34 files; production paths include
  `app/api/capture/route.ts` (5), `app/api/import/route.ts` (8),
  `app/api/chat/[sessionId]/messages/route.ts` (1), `lib/plexo.ts` (1).
- `instrumentation.ts` exists but only registers with Plexo core — no OTel SDK
  init.

**Implication**: OPTIMIZE-mode work (§15) is *gated out* until observability
is added. Phase T1 must land structured logging + spans before the queue
ranker can be tuned with data.

### 4c. Web is online-only

Beyond the missing SW: no IndexedDB / Dexie / localforage / idb anywhere in web
app code. Every page is fetch-on-mount. Mobile has the local-first story; web
does not.

### 4d. Settings page surface gaps

- `app/(app)/app/themes/[themeId]/route.ts:182-183` — explicit TODOs: Levio
  task search + Plexo session_logs both unimplemented; theme detail degrades
  silently.
- `app/(app)/app/graph/right-rail.tsx:129` — "Promote to Page coming soon"
  stub button (already hidden behind `cluster.isScl` per fix-batch C7).

### 4e. Two history routes

`/history` (Plexo conversation log, client-only) and `/web-history` (browser
extension page-visits, db-backed) look similar in the nav but back different
stores. High user-confusion risk + redo/cut likely.

### 4f. note_links — no backfill for pre-C3 corpus

- Auto-related populate: `app/api/capture/route.ts:171-182`.
- Manual wikilink: `app/api/notes/[id]/links/route.ts:47-50`.
- Unique constraint: `drizzle/0014_note_links_unique.sql`.
- Backfill script: **none**. Pre-C3 notes containing `[[wikilink]]`s do not
  surface in `note_links`.
