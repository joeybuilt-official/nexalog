# Nexalog Phase 0 audit — 2026-06-29

Strategic-pivot read: "focused Plexo-backbone showcase vs full Obsidian/Notion parity." Read-only audit, evidence-cited.

## 1. Data model — page-addressable, not block-addressable

**Verdict: page-addressable.** Blocks get UUIDs at the ProseMirror layer (`components/editor/block-id-extension.ts:53`, `crypto.randomUUID()` injected into every paragraph/heading/list-item via `appendTransaction`), and rendered as `data-block-id` DOM attrs (`block-id-extension.ts:28-31`). **But: the ID never crosses the HTTP boundary into the DB.** `notes.content` is a single `text` column (`lib/db/schema.ts:45`); `note_links` joins note → note only (`schema.ts:386-401`, `sourceNoteId`/`targetNoteId`, no block columns); no `block_id` / `block_ref` column appears in any of the 24 drizzle migrations (`drizzle/0001…0024`); zero references outside the extension file itself. Transclusion is `![[ref]]` text (`transclusion-extension.ts:10`) — `ref` is a free-form string parsed client-side, no FK. **One-way street: links/transclusion/backlinks all live at note granularity.** Roam-/Logseq-style block-refs would need a new join table + content-parsing migration.

## 3. Intelligence-boundary compliance — clean

**Zero forbidden imports.** Grep for `openai|@anthropic-ai|@google|ollama|@google/genai|vertexai` across source: **no matches** outside lockfile. Every AI call routes through `lib/plexo.ts`: `plexoAiComplete` (`plexo.ts:104`), `plexoEmbed` (`plexo.ts:132` — hits Plexo's bundled ONNX server, not OpenAI), `plexoClassifyCapture`, `plexoMemorySearch`. Embeddings worker confirms: `lib/enrichment/embeddings.ts:85 const vec = await plexoEmbed(text)`. Summary, tags, title-rescue, ideas, classification, brainstorm, chat — all via `plexoAiComplete`. `scripts/cluster-themes.ts` calls Plexo's `/api/v1/memory/cluster/compute` (`embeddings.ts:272`). **One nit: nexalog stores the vector in its own `nexalog.capture_sources.embedding` pgvector column (`drizzle/0011_pgvector_embeddings.sql`) — embeddings *compute* is Plexo, *storage* is local. Path B by design (`plexo.ts:113 comment`), not a violation.**

## 4. Plexo integration surface — moderate-thin

**34 files import `@/lib/plexo`** (grep, §3). `lib/plexo.ts` is 364 lines, single facade, single SDK client (`createPlexoClient` `plexo.ts:14`). The DEPENDENCY is thin — one npm pkg, one wrapper. The FEATURE % is high: ~70% of differentiated features go cold without Plexo (embed→search/related/themes/ideas; summary; long-summary; title-rescue; chat; brainstorm; classify; auto-tag). Pure-local features that survive Plexo outage: editor, FTS, journal CRUD, bookmarks list, typed-objects CRUD, multi-views, SM-2 review schedule, web-history, sync mutations, export. **Replaceable in days, not weeks** (one file, all calls return-null-safe — see `plexoEmbed` `plexo.ts:146 catch { return null }`).

## 5. Schema / RLS isolation — schema yes, RLS no

`nexalogSchema = pgSchema("nexalog")` confirmed `lib/db/schema.ts:18`; every table prefixed (e.g. `schema.ts:20,38,65,…`). **Zero RLS policies** — grep `CREATE POLICY|ENABLE ROW LEVEL SECURITY` across `drizzle/` returns nothing. Tenancy is enforced in app code by `userId text` + `workspaceId uuid` columns on every table, filtered in route handlers. Acceptable for app-owned-PG model; would NOT pass a multi-tenant SaaS audit. Invariant "per-app schema" holds; "RLS-isolated" doesn't.

## 7. One-way doors taken

1. **Tiptap stack** — only 716 LOC total of custom extensions (`block-id` 64, `slash` 206, `wikilink` 90, `transclusion` 55, `rich-editor` 235, `node-view` 66). Swappable to BlockSuite in a sprint; not a moat.
2. **`notes.content TEXT` single column** (`schema.ts:45`) — going block-addressable means content-parse migration + new `note_blocks` table + rewriting wikilink/transclusion/backlink resolvers to block granularity. Real cost: ~2 weeks.
3. **pgvector in `nexalog.capture_sources.embedding`** (drizzle/0011) — Path B is committed; moving vectors back into Plexo would dual-write.
4. **Plexo SDK 1.1.0 hard dep** (`package.json:21`) — `next.config.ts:8 serverExternalPackages` bakes it into the build.
5. **24 migrations applied**, several non-trivial (FTS generated columns, pgvector, typed-objects, sync log). Schema is real production weight now.
6. **Per-app PG schema with no RLS** — fine for v1, blocks a hosted-multi-tenant pivot without policy backfill.

No door taken that blocks the "focused Plexo-backbone showcase" pivot. Several doors taken that *raise* the cost of the "full Obsidian/Notion parity" pivot — specifically block-refs and CRDT collab.

## 8. Recommendation

**The audit supports the focused-showcase read, but for a sharper reason than the doc may state.** Nexalog is *already* a Plexo-backbone showcase by construction — 34 callsites, zero LLM-provider imports, embeddings via Plexo's ONNX, every smart feature degrades-to-null on Plexo outage. The cost has already been paid. What Nexalog is NOT — and what parity would require — is block-addressable, CRDT-collab, plugin-API, canvas, OCR, deep-research, custom-agents, multi-backend-sync. Each of those is a multi-sprint build with one-way-door schema or stack cost (block-refs alone ≈ 2 weeks; CRDT ≈ months). The honest framing: parity isn't "expand the audit" — it's a different product. The risk in the focused pivot is the inverse: if you trim to "Plexo-backbone showcase" you must also de-scope the half-built features in §2 marked Partial (multimodal capture, local-first sync, SRS without authoring) so they don't look broken in demos. The schema is already there; the marketing surface is what needs the cut.
