# Agent policy

This file is the agent-agnostic home for the guardrails in this repo. It used to live as a
tool-specific permission list (`.claude/settings.json`), which only the tool that read that file was
bound by. Because this project works with many agents and LLM platforms, the guardrails are stated
here as doctrine that applies to **every** agent, plus a tool-native mirror generated by
`scripts/sync-agents.sh` for whichever tool you actually use.

**What is mechanically enforced, honestly:** a tool-specific permission file can refuse the commands
below, but only for the one tool that reads it. The binding plane for everyone is **required CI**
(`.github/workflows/verify.yml`) plus branch protection — CI is a merge gate, not a sandbox, so treat
the rules below as absolute regardless of what your harness enforces.

## Never — destructive filesystem and privilege escalation

- Never `rm -rf` a root, home, or current directory (`/`, `~`, `.`, `*`), and never `shred`, `mkfs`,
  or `dd` to a block device.
- Never recursive mass-delete or mass-permission (`find … -delete`, `find … -exec rm`,
  `chmod -R`, `chmod 777`, `chown -R`).
- Never escalate privilege (`sudo`, `su`, `doas`, `runas`) or mass-kill processes (`kill -9`,
  `killall`, `pkill -9`).

## Never — history and branch destruction

- Never force-push, `--mirror`, or push a branch deletion to a shared branch. Normal PR flow only.
- Never `git reset --hard` a shared branch, `git clean -fd`/`-xdf`, `git checkout -- .`,
  `git restore .`, delete branches/tags, or rewrite history (`filter-branch`, `filter-repo`,
  `reflog expire`, `gc --prune=now`, `update-ref -d`).
- The one exception is your own unmerged PR branch: amending it and pushing with
  `git push --force-with-lease` is allowed — and is what the docs landing gate requires when a commit
  is missing its worklog line. Never a bare `--force`, and never once someone else holds the branch.

## Never — piping the network into a shell

- Never `curl … | bash` (or `sh`/`zsh`/`python`/`node`), `wget … | sh`, `wget -qO- … | …`, or
  `iwr … | iex`. Install from a trusted, pinned source.

## Never — publishing and releasing

- Never publish a package (`npm`/`yarn`/`pnpm`/`bun publish`, `cargo publish`, `poetry publish`,
  `twine upload`, `gem push`, `dotnet nuget push`, `mvn deploy`, `docker push`), and never deploy to
  prod or ship a signed mobile release build unless the task explicitly asks **and** a human has
  approved.

## Never — database destruction

This repo's database is the **shared Postgres**: the `nexalog` schema sits beside other apps'
schemas, so a destructive command here is not contained to this project.

- Never run a schema push/sync/reset: `pnpm db:push`, `drizzle-kit push`, `prisma db push`,
  `prisma migrate reset`, `typeorm schema:drop`/`schema:sync`, `supabase db reset`,
  `dotnet ef database drop`, `knex migrate:rollback --all`, `alembic downgrade base`,
  `manage.py flush`/`reset_db`, `db:drop`/`db:reset`/`db:schema:load`.
- Never apply a migration to the shared/production database without explicit human approval.
- Never create a table in `public`. Everything goes in the `nexalog` PG schema; auth lives in the
  shared `auth` schema via Better Auth.

## Never — reading and exfiltrating secrets

- Never read `.env` / `.env.*`, `*.pem`, `id_rsa*` / `id_ed25519*`, `.aws/**`, `.ssh/**`,
  `credentials.json`, or `service-account*.json` — in any directory, at any depth.
- Never hardcode a secret, and never print one into a log line or a commit. Env vars only.

## Never — machine-local loop state

Never commit machine-local Phalanx loop state: `.claude-state.json`, `TASKS.md`, `PROGRESS.md`,
`HANDOFF.md`, `.phalanx-*`, `.claude-runs/`, `.claude/settings.local.json`, `.playwright-mcp/`.
Untracking is not deletion: the files still live on the machine, so never `git add` one back and never
delete one to "clean up" — a running loop reads it.

## Always

- Start a new file with `// SPDX-License-Identifier: MIT`.
- Stop and get human approval before any change that is destructive, irreversible, or outside the
  approved scope.

## Where the tool-native mirror comes from

`scripts/sync-agents.sh` renders this doctrine (plus every rule module) into the native file your tool
reads. Never hand-edit a generated mirror; edit `AGENTS.md`, `.agents/rules/*.md`, or this file and
re-run `sh scripts/sync-agents.sh`.
